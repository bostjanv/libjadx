# ADR 0001: Strict mapping export and import; defer local/propagated renames

Status: export and bounded import safety decisions implemented; scoped parameter subset implemented; local/propagated follow-ups deferred, 2026-09-28.

Phase 5.2 requires native mapping export, parameter/local renames and
related-method propagation only where pinned Jadx and the matching GUI prove
the behavior. Declaration editing and strict Tiny v2 export are separate slices.

The pinned
[`MappingExporter`](https://github.com/skylot/jadx/blob/28ff15e4ae69950aebea110a13e5ab895d234dfc/jadx-plugins/jadx-rename-mappings/src/main/java/jadx/plugins/mappings/save/MappingExporter.java)
does export a `JadxCodeData` with a selected mapping format. Its implementation
deletes an existing single-file output before writing and catches/logs its own
exceptions instead of reporting success or omissions to a caller. That is
insufficient for this service's explicit path safety, external conflict and
truthful success contract. Existing `/project/settings` only attaches an
already existing mapping; it is not an import or export transaction.

The safe export uses mapping-io 0.8.0 directly, validates the accepted baseline
file as well as the loaded tree, combines observed native alias precedence and
additive LINE comments, and reparses owned bytes before publishing. A destination
must be new; same-directory hard-link creation provides atomic no-clobber
behavior, exercised against an existing owned name on the actual filesystem.
`ATOMIC_MOVE` is excluded because it may replace an existing destination.
Unsupported namespaces/options, unknown/duplicate records, unresolved keys,
native code refs and non-LINE styles fail closed. No partial mapping is offered.
Directory identities and path components are rechecked; the residual final
syscall race with directory replacement is documented, rather than claimed
to be eliminated. This is an operational output, never project persistence.
See [the export probes and gates](../phase-5-mapping-export.md).

PR #13 proves original semantic parameter positions through `MethodNode`,
`MethodGen`, `CodeRenameVisitor`, real-Jadx fixtures and matching-GUI resave.
Parameter edits now use `MTH_ARG` keys with mandatory source snapshot and
session/revision admission. Unsupported signature forms fail closed and the
collision policy conservatively treats all declared method variables as
potentially overlapping. See [scoped evidence](../phase-5-scoped-editing.md).

`forVar` remains insufficient as a public stable identity. The owned optimized
fixture changes a merged local's emitted SSA metadata under SIMPLE; FALLBACK
emits no declarations. Native keys are not bound to their originating settings
in `.jadx`. We do not expose a persistent local subset without a broader
settings/GUI retargeting proof. Existing native VAR renames on a parameter's
method are conservatively rejected as ambiguous rather than translated.
`JavaMethod.getOverrideRelatedMethods()` provides candidates, not a proof of
complete propagation. Local and propagation operations still return
`UNSUPPORTED_CAPABILITY`. This is a capability boundary, not a new persistence
format or architectural departure.

Follow-up work should use owned optimized-variable and inheritance fixtures,
verify native keys and matching-GUI resave, and design mapping output with
allowed-root, symlink, conflict, omission and failure behavior before adding
new routes. Mapping import now uses its own admitted transaction: captured strict Tiny bytes
are resolved against original full keys and the current engine/native/attached
state, the entire conservative merge is staged privately, and only one native
replacement can publish it. Matching effective values are no-ops; differing
aliases/comments conflict. The narrow attached prefix plus one native LINE
suffix is proved by real-Jadx and matching-GUI fixtures. No source path is
attached and no file is saved. Arbitrary composites and inner-class renames
remain unsupported; automatic engine aliases count as existing effective values.
This deliberately bounded subset avoids lossy Tiny-to-native reconstruction.
See [import evidence](../phase-5-mapping-import.md). Neither mapping operation
imports or exports scoped or propagated native edits. Codec output is
generated by mapping-io, never hand-formatted Tiny text.
